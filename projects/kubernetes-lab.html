PROJECT 03

PortCheck Network Port Scanner

A lightweight network utility for identifying open TCP ports and understanding the services exposed on a host.

Linux Bash Python Flask Netcat Networking DevSecOps

OVERVIEW

What I worked on

PortCheck started as a Cloud and DevOps bootcamp task to create a Bash script that accepts a target host and uses Netcat (nc) to check whether TCP ports are open.

I extended the task by adding a Flask web interface that allows the user to scan a controlled set or range of ports. Detected ports are displayed together with their common services and basic risk guidance, making the results easier to understand.

WORKFLOW

How it works

The user enters a target IP address or hostname through the web interface. The input is validated before being passed to the backend scanning process.

Flask then executes the Bash scanner, which uses Netcat to test TCP connectivity against the selected ports. Only ports that successfully accept a connection are returned to the application.

The results are mapped to common services such as SSH, DNS, HTTP and PostgreSQL before being presented through the web interface with simple risk guidance.

USER   →   FLASK   →   BASH   →   NETCAT   →   RESULTS

RESULTS

Scanning my environment

I tested PortCheck against my own local environment. The scanner identified several reachable TCP services and displayed the corresponding port, service and risk guidance.

For example, the scan detected services including SSH, DNS, HTTP and PostgreSQL. The risk indicator provides context about the potential exposure of each service rather than treating every open port as a vulnerability.

VERIFICATION

Checking the results

To verify the scanner results, I compared them with the listening TCP ports reported directly by Ubuntu using the ss networking utility.

This allowed me to confirm that the ports identified by PortCheck corresponded with services actually listening on the system.

DEVSECOPS

Handling input safely

One of the main learning objectives was understanding the security risk of passing user-controlled input to operating system commands.

The application validates the target and port values before execution. Port numbers are restricted to the valid TCP range, while the target input only accepts the expected hostname or IP address format.

When Flask starts the scanner, user values are passed as separate subprocess arguments instead of constructing a shell command directly from the submitted input. This reduces the risk of shell command injection.

RISK GUIDANCE

Making the results useful

I added simple Low, Medium and High indicators to make the scan results easier to interpret.

These indicators provide basic educational guidance based on the type of service detected and its typical exposure considerations. An open port does not automatically mean that a system is vulnerable — configuration, authentication, firewall rules and network exposure also affect the actual security risk.

REFLECTION

What I learnt

This project helped me understand TCP ports and listening services more practically by allowing me to compare the results from my own scanner with Linux networking tools.

I also gained hands-on experience with Bash scripting, Netcat, Flask integration and secure handling of user input. Most importantly, it showed me how a simple Linux command-line tool can be integrated into an application while still considering basic DevSecOps practices.
