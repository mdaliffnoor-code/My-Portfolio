PROJECT 03

PortCheck Network Port Scanner

A lightweight network utility for identifying open TCP ports, understanding exposed services and presenting basic security guidance through a web interface.

Linux Bash Python Flask Netcat Networking DevSecOps

OVERVIEW

Project overview

PortCheck began as a Cloud and DevOps bootcamp task focused on creating a Bash script that accepts a target host and uses Netcat (nc) to determine whether TCP ports are open.

The original command-line utility was extended into a Flask web application, providing a more accessible interface for scanning a controlled set or range of TCP ports.

Detected ports are presented together with their commonly associated services and basic risk guidance, making the scan results easier to understand while introducing practical networking and DevSecOps concepts.

WORKFLOW

How it works

The scanning process begins when a target IP address or hostname is submitted through the web interface. The input is validated before being passed to the backend scanning process.

Flask connects the web interface with the Bash scanner, which uses Netcat to test TCP connectivity against the selected ports. Ports that successfully accept a connection are returned to the application as detected open ports.

The results are then mapped to commonly associated services and displayed through the interface together with basic security guidance.

RESULTS

Testing the local environment

PortCheck was tested against a local environment to identify reachable TCP services and compare the results with services actively listening on the system.

During testing, the scanner detected services including SSH, DNS, HTTP and PostgreSQL. Each detected port is displayed alongside its commonly associated service and a basic risk indicator.

The risk information provides additional context around network exposure rather than treating every detected open port as a security vulnerability.

VERIFICATION

Validating the scan results

Scanner results were independently compared with the listening TCP ports reported directly by Ubuntu using the ss networking utility.

$ sudo ss -tlnp

This provides a second source of verification and helps confirm that the ports identified by PortCheck correspond with services actually listening on the system.

DEVSECOPS

Handling input safely

A key security consideration for PortCheck is the handling of user-controlled input before it reaches operating system commands.

Validation and controlled command execution are therefore applied between the web interface and the backend scanner to reduce the risk associated with passing untrusted values to system utilities.

01
Input Validation

Target and port values are checked before they are passed to the backend scanner.

02
Controlled Port Range

Port values are restricted to valid TCP port numbers between 1 and 65535.

03
Safe Command Execution

User values are passed as separate subprocess arguments instead of being inserted directly into a shell command.

RISK GUIDANCE

Making the results useful

Simple Low, Medium and High indicators provide additional context for interpreting the services detected during a port scan.

LOW

Lower exposure concern, although the service should still be configured and maintained securely.

MEDIUM

A service that should be intentionally exposed and protected with appropriate configuration and access controls.

HIGH

A sensitive service where unnecessary network exposure should generally be restricted.

These indicators are intended as basic educational guidance rather than a vulnerability assessment. An open port does not automatically indicate that a system is vulnerable.

Actual risk also depends on factors such as network exposure, service configuration, authentication, firewall rules, software versions and whether the service needs to be externally accessible.

REFLECTION

What I learnt

This project provided practical experience with TCP ports and listening services by connecting networking concepts with actual scan results from a Linux environment.

Comparing PortCheck results with native Linux networking tools also demonstrated the importance of independently verifying application output rather than relying on a single source of information.

The project also provided hands-on experience with Bash scripting, Netcat, Flask integration, input validation and safer execution of operating system commands.

Overall, PortCheck demonstrates how a simple Linux command-line utility can be developed into a web-based networking tool while incorporating basic DevSecOps considerations.
